AI NIDS — STEP 4: SCENARIO-HOLDOUT GENERALIZATION

This package creates:

    src\04_scenario_holdout_evaluation.py

PURPOSE

Step 3 used a random, stratified flow-level split. That baseline is valid, but
related flows from the same traffic scenario can appear in both training and
testing data.

Step 4 performs a stronger test:

1. Hold out one complete traffic scenario.
2. Train a fresh clone of the selected Step 3 pipeline using samples from the
   other seven scenarios only.
3. Test on every valid row in the held-out scenario.
4. Repeat for all eight scenarios.
5. Aggregate the results.

The Step 3 production model is NOT overwritten.

INSTALL

Extract NIDS_Scenario_Holdout_Step4.zip into:

    C:\Users\esumi\AI-NIDS-Project

Confirm:

    Test-Path .\src\04_scenario_holdout_evaluation.py

Expected:

    True

RUN

    python .\src\04_scenario_holdout_evaluation.py

The default creates a reusable 300,000-row sample pool. Each fold excludes the
held-out scenario from that pool and evaluates the full held-out Parquet file.

This requires eight fresh model fits. Depending on your computer, allow roughly
20–90 minutes.

FASTER TRIAL

    python .\src\04_scenario_holdout_evaluation.py `
        --training-pool-size 150000

STRONGER RUN

    python .\src\04_scenario_holdout_evaluation.py `
        --training-pool-size 500000

INTERPRETATION

It is normal for scenario-holdout performance to be lower than the random-split
result. A decline means the random baseline benefited from traffic patterns
shared between training and testing. The scenario-holdout result is the stronger
evidence of how the detector handles a new traffic campaign or operational day.
